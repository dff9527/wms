# N7 揀貨路徑優化 spike

## 本票實作

揀貨波次與任務清單依 `storage_locations.location_code` 做不分大小寫的自然排序，數字段以整數比較，因此 `A-2` 會排在 `A-10` 前。沒有儲位的任務排在最前，保留可見性，方便現場補資料。

本次排序只決定固定的站點順序，不改變 FIFO/FEFO 配貨、庫存保留或揀貨確認邏輯。

## 後續演算法方向（未實作）

- S 形路徑：依 Zone、Aisle 分組，相鄰走道交替由前往後、由後往前，適合規則矩形倉庫且計算成本低。
- Return 路徑：每條走道進出同一端，適合只取走道前段貨物或中間橫向通道較少的配置。
- 最短路徑：把儲位、通道交叉點建成帶權圖，先算站點間最短距離，再用 TSP heuristic（nearest-neighbor + 2-opt）排站；需維護實際倉庫拓樸、單向通道與禁行區。

## 建議資料需求

若要進入正式路徑演算法，儲位需結構化保存 Zone/Aisle/Rack/Bin，並另建通道節點、可通行邊、距離與方向限制。僅解析 location code 無法可靠反映實際步行距離。
